# 原型聚类改进方案总结

## 📊 问题诊断

你的观察**完全正确**！当前实现存在以下关键问题：

### 1. 原型固定不可训练 ❌
- **位置**: `src/mil_models/PANTHER/networks.py:62`
- **问题**: `fix_proto=True` (默认)，原型在 k-means 初始化后完全冻结
- **影响**: 无法通过反向传播学习任务相关的原型表示

### 2. EM 迭代次数少 ⚠️
- **位置**: `src/mil_models/model_configs.py:88`
- **问题**: `em_iter=3` (默认)
- **影响**: patch 到原型的分配不充分

### 3. 非端到端学习 ❌
- **流程**: K-means → 固定原型 → 3轮EM → 原型不更新
- **影响**: 原型与生存预测目标缺乏梯度连接

---

## 🚀 快速改进方案

### 方案一：最简单的改进 (立即可用)

只需修改两行配置！

```yaml
# 在你的配置文件中 (如 configs/TCGA-LUAD.yaml)
model:
  fix_proto: false  # 从 true 改为 false
  em_iter: 5        # 从 3 改为 5
```

然后重新训练:
```bash
python src/training/main_prototype.py \
    --config configs/TCGA-LUAD.yaml \
    --fix_proto False \
    --em_iter 5
```

**预期提升**: C-index +2-5%

3. **修改训练循环** (添加多样性损失):
```python
# 在训练循环中

total_loss = survival_loss + 0.01 * diversity_loss
```

**预期提升**: C-index +3-7%

## 💡 关键建议

### 1. 从简单开始
首先尝试**方案一**(只改配置)，验证端到端训练确实有效

### 2. 监控原型质量
使用以下工具:
- **t-SNE 可视化**: 原型是否分散
- **使用率分布**: 是否均衡使用所有原型
- **梯度范数**: 原型是否在学习

### 3. 防止原型崩溃
关键技术:
- 多样性正则化 (`diversity_reg=0.01`)
- 更小的原型学习率 (`proto_lr=5e-5`)
- 定期重置不活跃原型

### 4. 超参数调优
重要参数:
- `proto_lr`: 原型学习率 (推荐 1e-5 到 1e-4)
- `diversity_reg`: 多样性权重 (推荐 0.001 到 0.05)
- `em_iter`: EM 迭代次数 (推荐 5 到 7)
- `tau`: EM 正则化强度 (推荐 0.001 到 0.01)
